# Hair Studio

Hair for the generated MHR characters, in three sources that share one browser (Inspector → Character Generator → *Hair Studio*):

| Source | Key | What it is |
|---|---|---|
| Built-in | `<name>` | The MakeHuman CC0 styles of the hair bundle (unchanged). |
| Procedural | `proc:<preset>` | Native hair cards generated from guide curves (`ProceduralHair`). 17 presets (short, bob, shag, pixie, buzz, afro, curly, wavy, long, side-swept, three ponytails) + user presets. |
| Imported | `lib:<id>` | A style extracted from a user-supplied FBX/OBJ/GLB/DAE and fitted to the head (`HairLibrary`, `HairFitting`). |

All three end as the same `head_hair` mesh built in `buildRig` on the SHAPED body, skinned from the nearest body vertices, tinted by `HairTint`
and textured by the existing hair material — so colour, animation, export and head-shape changes need no special cases.
Nothing is bundled or downloaded: imported assets arrive only through `--import-hair` / the panel, and the licence field travels with each entry.

## Procedural generator (`src/CharacterGen/ProceduralHair.*`, pure data)
1. **Scalp**: head vertices (driven by the head joint) above a hairline (`hairlineFraction`: high on the forehead, lower at the temples, lowest at the nape).
2. **Guides** (`generateGuides`): the hair is a stack of RINGS around the head (3-9 rings, 36-72 columns; short hair gets more rings so each reaches the next). A ring's roots sit on the head ellipsoid at the hairline (lowest ring) up to the crown; rings are spaced evenly along the meridian ARC (polar angle), because equal height steps leave wide bare rings where the crown is flat. Each column is a 9-point guide grown by stepping along a flow field (down the sides, radial from the crown, away from the parting, swept to the side and back over the temples, forward over the forehead for a fringe), with lift, gravity that grows towards the tips, tip curl, ponytail pull to a tie point, a shell projection that keeps it lying ON the head (the shell is further out for volume: an afro stands ~9 cm off the skull; each ring is a few mm further out than the one below), and collision against the whole body (`BodyCollider`), so long hair rests on the shoulders. Front hair never hangs below the eyebrows: this is decided by the AZIMUTH of the column, not by its root depth (a crown root of a front column also runs down the face). **One hem**: a ring higher up is lengthened by the height between its root and the hairline root of the same column, so all rings end on one smooth line; measuring every length from its own root made each ring end higher than the one below it and the hair read as stacked tiers (a palm tree). **Crown whorl** (`whorl` slider): the rings do not converge on the top of the skull but on an off-centre point at the back of the crown (a side chosen by the seed; centred when `symmetric`), and the flow near it swirls tangentially, so the hair starts from a whorl like real hair. Every guide is at least twice the ring spacing long, so rings overlap. `GuideEdit`s replay deterministically.
3. **Sheets** (`generateCards`): a ring is NOT a set of loose strips: neighbouring guides are the edges of one continuous sheet (like the shells of the bundled styles), so the hem is a smooth function of position. Sheets are cut into "locks" of 1-4 columns (`thickness`), each a strip with 4 texture variants over its width; clumping pulls the columns of a lock together towards the tips, which opens gaps between locks and makes the hem read as separate locks. Curl/wave is mostly sideways and coherent across columns (a curl in depth makes a sheet fold over itself); frizz is small noise. A crown fan and a thin scalp LINER (the "hair cap" of game hair, dropped when it would take more than a third of a tight triangle budget) guarantee that no style shows bare skin. After the guides are sampled every ring is smoothed along and across its columns (then pushed out of the body again), which removes the creases and spikes the body collision leaves where long hair meets the shoulders. The ponytail tie sits 5.5 cm behind the skull and the tail only spreads into a tube past the tie, so the tail clears the head and ears. The triangle budget is a HARD limit: the layout drops columns first, then rings, and only below the smallest sensible layout (about 16 columns x 2 rings) the segments per column, down to 2; budgets down to 200 triangles are respected at every quality.
4. **Validation** (`validate`/`repair`): NaN, bad indices, zero-area triangles, UVs out of range.
Everything is a pure function of `Params` + scalp (own splitmix64 RNG), so a hairstyle is stored as its small parameter set (`qtmesh-hair-procedural-v1`).

## Fitting imported hair (`HairFitting.*`)
Normalise (crown width → head width × 1.12, top → head top, centred) → a *root band* near the skin is corrected: penetrating vertices are pushed out, nearby ones pulled in by `snug` with a smooth fall-off, weld groups move together, the displacement field is relaxed over the mesh → the outer silhouette is untouched → final push-out guarantee. Manual correction: move/rotate/scale, snug, clearance, flip front. Rebuilt on every character rebuild, so it follows head-shape changes.

## Persistence
`StudioConfig` (`qtmesh-hair-studio-v1`: style key, procedural params, fit, colour) is kept in QSettings by the editor and written as `<output>.hair.json` by `qtmesh character`. Library: `<AppData>/hair_library/imported/<id>/{meta.json,hair.qmh,texture.png}` and `presets/*.json` (`QTMESH_HAIR_LIBRARY_DIR` overrides). Duplicates are detected by an order-independent geometry hash.

## Adding hairstyles
* From the GUI: Hair Studio → *Import hairstyles* (path, author, licence, attribution).
* CLI: `qtmesh character --import-hair <file|folder> --hair-author A --hair-license CC-BY-4.0 --hair-attribution "…"`; then `--hair lib:<id>` (`--list-hair-library`).
* A file is split into one style per child node of the root that has geometry (else one per mesh). Y-up, facing +Z is assumed; use *flip* / rotation otherwise.
* Check the licence first: CC-BY needs attribution; non-commercial assets must not ship in commercial builds. The Vincent Freelance collection was not downloaded or bundled — import it yourself after checking its licence.

## CLI
`qtmesh character --seed 3 --hair proc:wavy --hair-param length=0.4 --hair-param curliness=0.6 --hair-fit scale=1.1 --save-hair-config h.json -o c.glb`, `--list-hair-presets`, `--hair-config h.json`.

## Tests / manual procedure
`ProceduralHair_test`, `HairFitting_test`, `HairLibrary_test` (UnitTests `--gtest_filter='Hair*:LibFixture*'`). Manual: generate a character, open Hair Studio, pick each preset and move sliders (live preview), import an OBJ/FBX collection, select a tile, adjust the fit sliders, export GLB/FBX and reopen the file; load with a narrow and a wide head (body shape sliders).

## Scalp paint and ears
- **Scalp paint** (`scalpWeights`, `BuildReport::scalp`, `SkinTextureOptions::scalp`): wherever the hair grows, the body's skin texture is shaded towards the hair colour with a stubble of darker dots (root colour), with an irregular hairline (the per-vertex weight is soft at the hairline and the bake adds noise to the edge). It applies to every hair style (bundle, procedural, library) of the native head and follows the hair-colour setting; the hair itself covers it, but the bare edges (sideburns, temples, the nape, thin or short hair) no longer show a plain skin patch next to dark hair.
- **Ears** (`addEarColliders`): the ears are the head vertices that stick out furthest sideways beyond the skull; each gets a collision sphere. The normal push of `BodyCollider` works along vertex normals, and an ear is a thin sheet, so a strand could pass through to its far side; a strand inside an ear sphere is now pushed out of it and towards the side, i.e. over the ear, never into the head. Strand roots ignore the spheres (they sit on the scalp next to the ear).
- **Stand-off from the REAL head**: the head ellipsoid is only an approximation; at the temples and cheeks it is wider than the face, so hair resting on it floated several cm off the face as flat dark panels with hard edges (visible from the front, worst with the Ponytail slider at 0 on long styles). Above the ears every strand point is therefore also pulled to within the shell's stand-off of the nearest REAL head vertex (`0.006 m + 0.09 m x shell offset`), so volume still works (an afro keeps its puff) but the hair follows the actual face.
- **Tied-back hair** (`ponytail` > 0): the flow is aimed at the tie from the first segment and gravity is damped until the tie (before, strands left the forehead pointing down and looped back up: a flap of hair over the forehead), and the hairline is raised by `0.04 x ponytail` (`effectiveHairlineOffset`, also used by the scalp liner and the scalp paint). The first ring's roots are feathered: every strand of the texture starts a little way down from the root (up to 7.5 % of its length), and the scalp liner begins where the first ring of roots does, so the hairline is ragged with the painted scalp showing, not a hard cap edge (visible where alpha-to-coverage works, e.g. the viewport; offscreen renders draw the cut texels).
- **No switches at 0**: every rule that depends on `ponytail` has a strength that follows its value (`tieStrength = 1.5 x ponytail`, the brow limit fades out between 0.4 and 0.9), instead of being on at exactly 0 and off for anything above it. Before, a strand that passed the tie was flagged as a free tail for ANY ponytail > 0, which turned off the shell, the stand-off and the cling for the rest of the strand: 0.01 looked nothing like 0. `EveryParameterIsContinuousAroundZero` pins this for the main sliders (a 0.01 change must not move the hair by more than 1.2 cm on average).
- **Low ponytail values** (0.01-0.3) used to grow a curl / spike pointing up at the ear and the shoulders, longer the lower the value: (1) the ear sphere pushed a strand up as well as out, and the strand's next direction is recomputed from that displacement, so it kept pointing up (the push is now sideways only, and a strand below the crown rises at most 15 % of a segment per step, fading out as the hair is tied back); (2) the cling limit faded to 'none' LINEARLY with the tie strength, so 5 % ponytail already more than doubled it and hair flared out where it rests on the shoulders (the fade is now a smoothstep from 0.35, i.e. it stays put until the hair is really tied back).
- **Brow limit is a floor, not a pull**: it used to lerp every strand point towards the brow line by its front-ness on EACH step; a strand hanging low along the cheek at a partly-front angle (front-ness 0.3) was dragged up by 30 % of the whole gap per step, i.e. long hair pointing up at the front (worst on long wavy / straight and the curly styles, with Ponytail at 0). It is now `y = max(y, lerp(chin - 0.4 m, brow, front-ness))`, which only bites where the point really is in front of the face, and the front-ness window is narrower (about +-55 degrees). Gravity also leans slightly backwards for hair at the sides of the head. `HangingHairNeverClimbsBackUp` pins it.
- **Cling**: below the ears hair hangs free and keeps its sideways momentum, flaring out like a skirt; it is now pulled (horizontally only, never up) to within a few cm of the nearest body point.

## Texture
`bakeCardTexturePng`: each of the 4 columns is a seamless, horizontally periodic tile of one lock: ~30-42 strands, each with its own brightness and its own length (the hem frays into single strands), darker at the root and at the lock edges, a soft sheen. Texels past a strand's end have alpha 0 but KEEP hair-coloured RGB: where alpha-to-coverage has no multisample buffer to act on (offscreen RTT renders, some viewports) they are drawn anyway, and black RGB under them showed up as dark holes.

## Known limitations
No viewport gizmo for guide editing yet (guide edits exist in the data/JSON and tests, not as a draggable UI); thumbnails exist for imported styles only (silhouette); braids, fades and tight coily patterns are not modelled; no hair physics; hair is skinned from the nearest body vertex, so long hair follows the neck/shoulders rigidly; the GUI does not yet write the sidecar on export (the CLI does); the Sketchfab collection must be imported by the user.

## Library details
- **Removing a library hairstyle** moves its folder to `<library>/trash/` instead of deleting it (the editor's undo history may still have to rebuild a character that used it); `load()` still finds it there, `list()` does not, and the trash is emptied at the next start (`purgeTrash`).
- **Saved presets** are one file per EXACT name (a hash of the name is part of the file name; the real name is stored inside), so `Long/curls` and `Long?curls` cannot overwrite each other.
- **Entries that cannot be read are never registered**: `save()` refuses what `decode()` would (more than 5 M vertices / 30 M indices, an index count that is not a multiple of 3, non-finite positions), and `load()` treats a `meta.json` that is not a JSON object as a damaged entry. The id `.` (and any id starting with a dot) is invalid, so `remove()` can never address the whole imported folder.
- **A style whose parts use different materials** is merged into ONE mesh with ONE texture: the part textures are stacked into an atlas (common width) and each part's UVs are remapped into its own band, inset by half a texel against filtering bleed; a part with no texture gets a flat opaque tile; a material that has only an opacity map keeps it (constant diffuse colour sized to the opacity map); an absolute texture path is tried as it is before the model's folder.
- **The fit of a library entry** (its saved correction, e.g. a flipped front) applies in the CLI and MCP too unless the caller passes a fit; `--hair-fit` is rejected for `proc:` styles (it only moves imported hair), and `autoFit = false` means the source exactly as it is, moved only by the adjustments.
